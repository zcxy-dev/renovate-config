# renovate-config

The Renovate preset that zcxy-dev repositories extend with `"extends": ["github>zcxy-dev/renovate-config"]` in their `.github/renovate.json`. Every repository extends it except HTT (another owner's code) and htt-payroll (keeps Dependabot until it retires). This README is the one description of the preset; `default.json` is the preset itself, and its `description` fields only label each rule.

It is public so Renovate can read it from any repository, whatever that repository's visibility. Change `default.json` by pull request; the `validate` check runs `renovate-config-validator --strict --no-global` on it and on this repository's own `.github/renovate.json`, on a GitHub-hosted runner.

## What the preset does

Renovate updates every extending repository's dependencies; Dependabot only raises alerts.

- **Base.** `config:best-practices`, so it covers npm and pnpm, Python (`pyproject.toml`, `requirements*.txt`, `uv.lock`), mise, `.node-version` and `.python-version`, Dockerfiles and GitHub Actions, with every action and Docker image pinned to a digest, development dependencies pinned to exact versions, lock files refreshed weekly (Monday before 04:00), and a pull request when Renovate retires a config option. Commits use semantic messages with the scope `deps`, and every pull request gets the `dependencies` label.
- **Dependency Dashboard.** Each repository has a "Dependency Dashboard" issue listing pending, waiting and failed updates; ticking an update there opens it at once.
- **Schedule.** Updates open Mondays 00:00-03:59 Asia/Taipei, so they don't compete with daytime work for the self-hosted runner. There is no hourly cap on new pull requests (`prHourlyLimit: 0`). Security updates and the shared-workflows pins open at any time.
- **Seven days old.** A release is offered only once it is seven days old (`minimumReleaseAge`, npm included), so a compromised release is usually pulled before it reaches a repository. Exceptions: Docker images, whose tags carry the date of their last push rather than of their release (official images are rebuilt under the same tag every few days, so they would never come of age), Node and the Python interpreter (below), and lock-file maintenance and version pins, which have no release date to wait for. Lock-file maintenance resolves to the newest releases, so it waits for a person to merge it.
- **Grouped.** One pull request each for the npm, Python, mise, Docker and GitHub Actions minor and patch updates. Playwright's packages have their own group (a new version needs new screenshot baselines and the matching browser image, which is not in the group: each repository keeps the image tag in its scripts and moves it by hand), and Next.js with its packages and OpenNext move together (OpenNext supports a narrow range of Next.js versions); both are matched by their source repository. A major still opens apart from its group's minor and patch updates.
- **Majors wait for approval.** Every major update opens only once it is ticked on the Dependency Dashboard; so does a Python minor, which opens apart from the interpreter's patch updates and, like a major, waits for a person to merge it.
- **Node and Python.** Node moves in one pull request wherever it is named (the Docker image, `.node-version`, mise, `engines`), and so does the Python interpreter (`.python-version`, the python image, mise), so files that must match never land apart. Both skip the seven-day wait, since their Docker images never come of age and a group would never complete.
- **Merged on its own.** Minor, patch, pin and digest updates (`pinDigest` included) merge through GitHub's auto-merge once the required checks pass, in every repository; an approved major waits for a person to merge it.
- **Security updates.** Renovate turns each Dependabot alert into a pull request at once, labelled `security`, without the seven-day wait (Renovate's default for `vulnerabilityAlerts`). Dependabot security updates are off in every extending repository, so the two never open the same update.

## Using it in a repository

`.github/renovate.json` is `{"extends": ["github>zcxy-dev/renovate-config"]}`, plus only the repository's own additions, each with its reason: an update group its checks do not cover, which waits for review, or a manager the base does not set up right for it (requirements files compiled with hashes by `uv pip compile` need the `pip-compile` manager, with `pip_requirements` off for them). Validate it with the validator version `.github/workflows/validate.yml` pins: `npx --yes --package renovate@<version> -- renovate-config-validator --strict --no-global .github/renovate.json`.
